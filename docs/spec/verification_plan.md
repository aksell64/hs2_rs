# План верификации Quint-модели

Что уже проверяется: safety-инварианты `safety_inv` (agreement, монотонность lock / voted_view / high_qc /
exec_height, один QC на view, lock protection, certified extends justify) на симуляциях `step` и `step_fair`.

Ниже — что ещё нужно проверить, и как.

---

## 1. Liveness в Quint: как её проверять

Симулятор liveness не доказывает, но проверить её можно тремя способами.

1. **Temporal-свойства через Apalache (`quint verify`).**
   В Quint есть `temporal`-определения (`always`, `eventually`, `weakFair`, `strongFair`); Apalache ищет
   контрпример в виде «петли», на которой событие так и не наступает.
   Ограничения:
   - проверка ограничена глубиной (bounded);
   - без fairness почти любая liveness ложна (можно вечно ничего не делать);
   - детальная модель для Apalache тяжела — реалистично только на абстрактной модели протокола.

2. **Ограниченная liveness как инвариант в симуляторе.**
   «В конце концов» заменяется на «не дольше N шагов»: ghost-счётчик шагов с последнего события и инвариант
   вида `steps_since_commit < N` в режиме `step_fair`. Не доказательство, но залипания (как было с лидером
   в Case 2) симулятор находит трассой.

3. **Свидетели и статистика (`--witnesses`).**
   «В скольких трассах из 500 был коммит», «в скольких узел так и не вошёл во view v». Слабее, но дёшево.

## 2. Калибровка инвариантов мутантами (обязательно)

Без этого неизвестно, способны ли инварианты вообще упасть. Мутанты запускаются `tools/mutants.py`
(см. README): каждая запись — замена строки в копии спеки и проверка симуляцией или тестом.
Цель — у каждого инварианта и каждого правила протокола свой мутант, который ловится.

Сделано:

| мутант | что ломает | чем ловится |
|---|---|---|
| `no_lock_check` | убран `justify.view >= qc_lock.view` из `can_vote` | `voteRespectsLockTest` (симуляция `lock_protection_inv` не ловит) |
| `lock_any` | лок обновляется без сравнения | `lockNeverDecreasesTest` (и симуляция `lock_monotonic_inv`) |
| `no_lock_check_vs_old_qc` | `no_lock_check` на всех + византийский лидер на genesis QC | симуляция `lock_protection_inv` |

Нужно:

- [ ] `no_leader_check` — driver принимает предложение от любого отправителя; ловится готовым
  `proposalFromNonLeaderIsIgnoredTest`, нужна только запись в `MUTANTS`.
- [ ] `double_vote` — убрать `voted_view < view`; тест: два предложения лидера в одном view, реплика отправляет
  один голос (считать `VoteMsg` в inbox лидера v+1). Симуляцией `once_qc_in_view_inv` не откалибровать:
  коллектор держит один голос от отправителя и один QC на view, поэтому второй QC не соберётся даже при
  двойных голосах честных (проверено: `double_vote` на всех + `equivocate` — нарушения нет). Для симуляции
  нужен византийский коллектор (n = 7, два византийца подряд: эквивокатор и лидер следующего view).
- [ ] `no_extends_justify` — убрать `parent == justify.block`; тест: `inject` блока с `parent ≠ justify.block`,
  реплика не голосует (нужен вариант `proposal` с явным `parent`). Покрывает `ancestry_inv`.
- [ ] `high_qc_any` — pacemaker берёт любой QC в `high_qc`; тест: предложение со старым `justify` не понижает
  `high_qc` (можно дописать в `lockNeverDecreasesTest`). Покрывает `high_qc_monotonic_inv`.
- [ ] `commit_any_views` — убрать `justify.view == b_prime.justify.view + 1` в `update`; тест: два QC через
  пропущенный view, коммита нет. Покрывает правило коммита / `agreement_inv`.
- [ ] `exec_backwards` — убрать `b.height > exec_height`; тест: повторный коммит не откатывает `exec_height`.
  Покрывает `exec_monotonic_inv`.

## 3. Недостающие safety-инварианты

- [ ] **I3, вторая часть:** голос во view v ⇒ `voted_view ≥ v`; честный узел не голосует дважды в одном view.
- [ ] **I4:** `high_qc` — максимум по view среди обработанных QC.
- [ ] **Pacemaker:**
  - `high_qc.view < cur_view` (на этом держится `HighQCApplied`);
  - честный лидер предлагает не больше одного блока за view;
  - `lock_timer` взведён только у лидера в Case 2.
- [ ] **Хранилище:** у каждого блока в `kv` есть все предки (на этом держится контракт blocksync).
- [ ] **I9, I10:** голос соответствует локу голосующего; лок стоит на реальном QC. Нужна история голосов (ghost).

## 4. Ограниченная liveness при справедливом планировщике (`step_fair`)

- [ ] два подряд честных лидера ⇒ коммит за N шагов;
- [ ] все честные узлы приходят в один view за N шагов (view sync);
- [ ] узел, пропустивший блок, снова начинает коммитить.
  **Сейчас должно падать**, пока `BlockSynced` не обрабатывается — проверка, что blocksync нужен и потом помогает;
- [ ] блок честного лидера с кворумом голосов в конце концов коммитится.
  **Должно падать из-за tail-forking** — задокументированная особенность, а не баг.

## 6. Усилить византийскую модель

Два механизма:

- `deliver_faulty` (узлы `FAULTY`) — случайный мусор, широкий поиск;
- мутанты с `byzantine` в `tools/mutants/` (узлы `BYZANTINE`) — честный код с одним изменённым правилом,
  `expect = "safe"`: safety обязана держаться.

Сделано:

- `vote_past_lock` — византиец голосует мимо лока. Держится, но почти вхолостую:
  отклонение в 1–6 трассах из 300 в `step`, 0 в `step_fair`;
- счётчик отклонений: ghost-поле `c.deviations` и свидетель `deviation_witness` (число трасс с отклонением);
- `propose_old_qc` — византийский лидер строит блок на genesis QC вместо `high_qc`. Отклоняется почти в каждой
  трассе (299 из 300), safety держится в `step`, `step_fair` и вместе с `vote_past_lock`;
- `silent` — византиец всё обрабатывает, но ничего не отправляет (в `sm.qnt`). Safety держится, коммиты в
  `step_fair` идут;
- `tail_fork` — византийский лидер v+1 строит на QC(v−1) вместо QC(v). Форк получает QC
  (`tail_fork_witness`) в 276 трассах из 300; safety держится. Без атаки, при всех честных, tail-fork
  бывает в ~24 трассах из 300 — из-за модели таймеров (§8);
- `equivocate` — византийский лидер шлёт каждому узлу два блока своего view (в разном порядке чётным и
  нечётным); `equivocate_and_double_vote` — плюс византиец голосует за оба. Safety держится.

Нужно (все — мутанты с `byzantine` и `expect = "safe"`):

- [ ] `byz_stale_status` — в Case 2 шлёт status со старым QC;
- [ ] `byz_no_relay` — не ретранслирует TC;
- [ ] `deliver_faulty`: голоса только за существующие блоки и только нужному лидеру, предложения для актуальных views;
- [ ] эквивокация разным узлам — через Twins (византиец = два честных экземпляра с одним id).

## 7. Индуктивный инвариант (Apalache)

Отдельная абстрактная модель протокола (подход ChonkyBFT) и `IndInv` из `invariants.md`.
Единственный путь к safety для любой длины трассы, а не «в N трассах ничего не нашли». Большая отдельная работа.

---

## 8. Что модель пока не покрывает

- сеть FIFO: перестановки сообщений не исследуются;
- нет перезапуска узла (восстановление `qc_lock` и `voted_view`);
- `BlockSynced` не обрабатывается, предложение с неизвестным родителем отбрасывается вместе с его QC;
- `step_fair` допускает tail-fork без византийцев: следующий лидер может уйти по таймеру из v, не дождавшись
  голосов, а lock-таймер срабатывает без учёта P_pc + Δ; тогда он предлагает на QC(v−1), а QC(v) собирается позже;
- `protocol.md` расходится с моделью: убран `onHeardAll`, добавлена буферизация будущих предложений,
  допущение `P_pc + Δ < τ`.
